# Product

## Register

product

## Users

Sunshine Travel operators, local demo owners, support staff, and developers who need one Windows application to inspect and exercise passenger, driver, and admin workflows without jumping between miniapp dev tools, browser tabs, and backend probes.

## Product Purpose

The desktop client unifies passenger ride actions, driver dispatch work, and operations management into one task-first Windows surface. Success means a user can demonstrate, test, and operate the full Sunshine Travel loop from booking to driver fulfillment to admin review with clear state, graceful offline mock data, and direct links to the backend contract.

## Brand Personality

Calm, precise, warm. The UI should feel polished and light like a native Apple productivity tool while preserving Sunshine Travel's orange accent and mature travel-service tone.

## Anti-references

Avoid dark tech dashboards, decorative glow effects, oversized landing-page heroes, AI-looking bento decoration, purple gradients, novelty controls, and modal-heavy workflows. Do not mimic mobile screens one by one when a desktop workflow can show more context.

## Design Principles

1. One cockpit, three roles: passenger, driver, and admin should feel connected but never confused.
2. State before decoration: every animation, chip, and panel exists to clarify order, connection, payment, review, or audit state.
3. Real data when available, useful demo data when offline: backend failure should downgrade the app, not strand the user.
4. Desktop density with mobile warmth: show more operational context than the miniapp while retaining the existing warm-orange Sunshine identity.
5. Every action exposes consequence: destructive, financial, audit, and status-changing actions must show the next state immediately.

## Accessibility & Inclusion

Target WCAG AA contrast, keyboard-operable controls, visible focus states, reduced-motion support, semantic labels for icon buttons, and status text paired with color so color is never the only signal.
