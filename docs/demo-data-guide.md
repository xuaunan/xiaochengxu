# 预置数据导入说明

这份说明只做一件事：把管理后台里的用户、司机、订单、优惠券、轨迹、投诉、财务数据一次补齐，让数据大盘不再是 0。

## 先看你要用哪种方式

### 方式 1：项目重启自动导入

适合你想一劳永逸，以后每次重启后端都自动带出预置数据。

你要用的文件：

- `sql/data.sql`

操作步骤：

1. 在 IDEA 里打开你当前正在运行的后端项目。
2. 找到后端资源目录，一般是 `src/main/resources/`。
3. 看一下这个目录里有没有 `data.sql`。
4. 如果已经有 `data.sql`：
   把现在仓库里的 `sql/data.sql` 内容全部复制过去，覆盖原内容。
5. 如果没有 `data.sql`：
   在 `src/main/resources/` 下新建一个 `data.sql`，把 `sql/data.sql` 的内容完整粘贴进去。
6. 如果后端项目里还有 `schema.sql`：
   保持它不动即可。`data.sql` 负责塞预置数据，`schema.sql` 负责建表。
7. 停掉后端，再重新启动一次。
8. 启动成功后，打开管理后台和 `http://127.0.0.1:8080/doc.html`。
9. 进入管理后台后点一下“管理员快捷登录”。
10. 再打开数据大盘、用户管理、司机管理、订单管理、营销中心，就能看到完整预置数据。

如果重启后还是没数据，优先检查这 4 件事：

1. `data.sql` 是不是放在了真正后端项目的 `src/main/resources/` 里。
2. 后端是不是连的 `sunshine_travel` 这个数据库。
3. 启动日志里有没有 `Table ... doesn't exist` 或 `Duplicate entry`。
4. 旧数据库里是不是还有一套结构不一致的数据。

### 方式 2：直接在 MySQL 里手动导入

适合你想马上把数据库清干净，然后一次性重建成完整预置库。

你要用的文件：

- `sql/sunshine_travel.sql`

操作步骤：

1. 打开 Navicat、DataGrip、MySQL Workbench，或者你平时能连 MySQL 的工具。
2. 连上你项目用的 MySQL。
3. 新建一个查询窗口。
4. 打开仓库里的 `sql/sunshine_travel.sql`。
5. 全选全部 SQL。
6. 直接执行。
7. 这份脚本会自动做 3 件事：
   创建 `sunshine_travel` 数据库。
   重建项目用到的核心表。
   插入完整预置数据。
8. 执行完成后，把后端配置里的数据库名确认成 `sunshine_travel`。
9. 重启后端。
10. 重启完成后再打开管理后台和 Knife4j 文档进行验证。

如果你只想补数据、不想重建数据库：

1. 先确认当前数据库表已经建好。
2. 打开 `sql/data.sql`。
3. 全选执行。
4. 这份脚本支持重复执行，不会因为同一批固定预置数据重复导入而直接报错。

## 轨迹模式说明

司机端默认使用“规划轨迹”模式。

规划轨迹模式下，司机接单后会在上车点附近生成司机位置，优先按地图道路规划路线推进小车位置，并持续更新轨迹。管理后台订单详情只展示行驶时长、已行驶距离和路线进度，不展示具体经纬度。真实定位模式需要在司机端“接单设置”中手动切换。

本轮轨迹模式、取消闭环和大盘优化的详细改动见：`docs/change-log-2026-05-14.md`

## 最稳妥的推荐

业务验证前，优先用一次 `sql/sunshine_travel.sql` 全量重建。

原因很简单：

1. 最干净。
2. 最不容易受旧数据影响。
3. 后台看到的结果最稳定。
